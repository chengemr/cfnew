v4.0.6 优化订阅来源读取和大列表处理，并为管理保存接口补齐流式正文保护。订阅链接、管理认证、代理身份、KV 数据格式及兼容日期 `2026-01-20` 保持兼容。

## 优选来源

- 同一 Worker 实例内按来源缓存解析结果 3 分钟，合并并发请求；不同订阅格式共用来源数据，生成的订阅和代理凭据不进入缓存。
- 刷新失败时可使用成功获取后 15 分钟内的旧节点，重试间隔至少 15 秒，失败不延长旧节点寿命；旧数据过期且其他启用来源也无效时返回 503。
- 来源关闭、URL 切换及当前请求的协议、DNS、ECH、IP 家族和 ISP 筛选继续生效。
- 多 URL 最多 16 个，同时读取最多 4 个，按配置顺序合并；保留原节点命名格式，响应快慢不再交换节点编号。
- 每个远程来源及订阅总计最多采用前 1024 条有效来源节点。内置源先分别保留各分组的有界数据，再应用当前请求筛选。缓存最多保存 32 个来源。

## 资源保护与性能

- 移除大数组的展开调用，修复约 692 KiB、4.5 万节点清单触发 HTTP 500 的问题；该清单现在按顺序生成有界订阅。
- 同协议、传输和 TLS 组合的固定查询参数只编码一次，避免为每个节点重复构造；优选 API 使用集合去重。
- 协议展开和最终订阅各限制为 4 MiB，超过时返回 422，提示缩减节点或配置字段。
- 家宽源正文最多 8 MiB，按原速度排序最多采用 100 个有效落地节点；限制重复证书锚点数量，兼容常见 YAML 解码器的限制。
- 配置与优选写请求正文最多 512 KiB，5 秒内未读完返回 408，正文超限返回 413；取消正文读取并释放读取锁与计时器，失败不写 KV。
- 优选 API 单批及保存列表最多 1024 个节点，超限整批拒绝；已有较大的列表仍可读取、删除或通过配置接口缩减。登录保留原 4 KiB／5 秒与 400／408 行为。
- 前端与后端逐项验证多 URL 优选来源，防止第二个 URL 绕过 HTTP(S) 校验。

## 下载与升级

- **Pages.zip**：ZIP 根目录仅包含 `_worker.js`，可直接用于 Pages。
- **_worker.js**：明文 Worker。
- **_worker.obfuscated.js**：混淆 Worker；用于 Pages 时重命名为 `_worker.js`。
- **SHA256SUMS.txt**：三个部署文件的 SHA256 校验值。

保留现有 `u`／`U`、独立 `ADMIN_TOKEN`、KV 绑定 `C`、域名和路径，上传新部署文件，然后刷新客户端订阅。首页和管理页应显示 **v4.0.6**。节点数超限时按原来源优先级取前部；需要更多节点时应拆分列表或部署。
