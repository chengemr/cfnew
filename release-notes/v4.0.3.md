- **_worker.js**：可独立部署的明文 Worker。

- **Source code**：开发源码，不是 Pages 部署包。

下载 `Pages.zip` 上传到可正常部署的 Pages 项目。保留原环境变量、有效的 `u`／`U`、KV 绑定 `C`、域名和管理路径，兼容日期继续使用 `2026-01-20`，不需要迁移 KV。部署后首页和管理页应显示 **v4.0.3**。

## 具体行为变化

- **DNS 持续收发**：上传和下载独立，复用同一上游 TCP 连接，上游保持连接时后续查询仍能发送并收到响应。DNS 长度前缀原样保留，支持分片及多帧，VLESS 响应头只发送一次。等待完整回答停滞 5 秒、已回答后空闲 45 秒、异常或客户端断开时清理连接、流锁与计时器；超时清理不等待 WS 关闭握手确认。
- **WS 入口保护**：early data、ReadableStream 积压、等待建连／握手、上传队列和正在写入的字节共用 256 KiB 限额，超过时立即关闭并取消待连接任务。写入完成才释放计数；5 秒内未完成首包认证会关闭，VLESS／Trojan 认证成功或连接结束后清除期限。
- **订阅失败保护**：所有启用来源均没有有效节点时，Base64、Clash、Sing-box 等格式返回 HTTP 503、清晰错误正文和 `no-store`，不再返回 `127.0.0.1` 占位节点，也不擅自开启其他来源。有其他有效的启用来源时继续正常生成；最近成功节点缓存未实现。
- **文档纠正**：没有每 15 分钟后台优选任务；ECH 配置由支持的客户端获取，Worker 只输出参数；未配置有效 `s` 时 `qj=only` 拒绝直连。这些文档纠正不改变既有出站策略。

保留原 KV／Env／路由、节点字段和顺序、DNS `8.8.4.4:53` 目标、VLESS／Trojan／WS／XHTTP 接收范围，以及 `scu`、轻量版和 snippets 兼容入口。现代 `src/` 修复未同步到两个旧独立部署入口。

## 部署验收与限制

发布不会自动部署用户 Cloudflare 项目或修改生产 KV。部署后建议重点测试：同一客户端连续 DNS 查询、WS／XHTTP 实际连接、配置保存与刷新、三种订阅更新，以及 `qj=only` 的上游出口。全部来源失败时应收到 503，客户端是否保留旧配置由客户端决定；异常时可回滚上一部署。

**管理权限共用是独立后续任务，尚未修复。**绑定 KV 后，订阅链接持有人可推导配置 API 并读写配置；`ae=no` 只限制优选 API，不能保护配置接口。分享订阅前需要拆分独立管理凭据。

公网 Pages／Worker 部署、实际客户端 TLS／代理出口验收未执行，由用户部署后测试。本地和 CI 检查不能代替公网验收。KV 跨 isolate 仍为最终一致；原版 Base64 的原始 Unicode 主机名应使用 punycode 序列化形式。其他限制见 [Pages 更新说明](https://github.com/chengemr/cfnew/blob/v4.0.3/PAGES-UPDATE.md)。
